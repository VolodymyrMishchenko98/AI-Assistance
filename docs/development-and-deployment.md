# Разработка и эксплуатация на разных компьютерах

## Назначение машин

- **ASUS TUF Gaming F15** — только разработка: архитектура, код, тесты,
  отладка и эксперименты. Его вычислительная мощность не является основанием
  выбирать архитектуру или модель.
- **Lenovo IdeaPad Slim 5i** — целевая среда эксплуатации: Windows,
  Intel Core i5-13420H, 16 ГБ RAM и интегрированная Intel Graphics.

Функциональность, зависимости и локальные AI-модели должны быть совместимы
с Lenovo. Не предполагать наличия CUDA, NVIDIA GPU или IDE. Итоговые
производительность и потребление памяти измерять непосредственно на Lenovo.

## Текущее состояние

Репозиторий пока содержит только документационный каркас: исходного кода,
сторонних зависимостей и AI-моделей нет. Принятое архитектурное решение
Modular Monolith + Clean Architecture и границы модулей описаны в
[architecture.md](architecture.md),
[module-boundaries.md](module-boundaries.md) и принятом
[ADR-0001](decisions/0001-modular-monolith.md). Price Checker — единственный
модуль MVP, но MVP ещё не реализован и не готов к выпуску. Автоматический поиск
товаров через бесплатный источник обязателен; конкретный источник, формат
отчёта и критерии производительности ещё предстоит выбрать или проверить.
Ручная вставка URL является резервным сценарием, если автоматический поиск
недоступен. Выбранные зависимости фиксировать с версиями, а Python —
закрепить на конкретной поддерживаемой версии.

Предложение Price Checker MVP предусматривает ручное добавление нескольких
позиций или импорт `.xlsx` с предпросмотром, сопоставлением колонок и
построчной валидацией. Разбор договоров и OCR остаются за рамками MVP и
относятся к будущему Document Intelligence. Эти сценарии пока описаны только
в документации и не реализованы.

В `pyproject.toml` сейчас задан предварительный нижний предел Python 3.11;
это не окончательная фиксация версии среды.

## Подготовка ASUS (разработка)

1. Установить Git и согласованную версию Python для Windows.
2. Клонировать репозиторий либо получить изменения через Git:

   ```powershell
   git clone <URL-репозитория>
   Set-Location <папка-проекта>
   ```

   Для уже клонированного проекта:

   ```powershell
   git pull
   ```

3. Не добавлять существующую `.venv` в Git и не переносить её на другой
   компьютер. Этот каркас не требует устанавливать пакеты. Не пересоздавать
   и не изменять уже существующую `.venv` только ради подготовки каркаса.
4. Архитектура уже согласована, но приложение пока не запускать: функционального
   модуля ещё нет.

## Первичная установка на Lenovo (эксплуатация)

1. Установить Git и Python для Windows независимо от IDE.
2. Клонировать проект:

   ```powershell
   git clone <URL-репозитория>
   Set-Location <папка-проекта>
   ```

3. Проверить наличие Python и Git:

   ```powershell
   py --version
   git --version
   ```

4. Не копировать `.venv` с ASUS. После согласования целевой версии Python
   создать отдельную среду на Lenovo и установить только зафиксированные
   проектом зависимости. Конкретные команды установки и запуска будут
   добавлены вместе с архитектурой и проверены на Lenovo.
5. Сейчас приложение не запускается: функциональные модули ещё не созданы.

## Перенос через Git без конфиденциальных данных

- Перед коммитом проверять список файлов и изменения:

  ```powershell
  git status --short
  git diff --cached --name-only
  git diff --cached
  ```

- Добавлять только ожидаемые файлы проекта; не использовать без проверки
  `git add .` или `git add -A`.
- `.gitignore` исключает локальные виртуальные окружения, `.env`, закрытые
  документы, локальные базы данных, логи, результаты обработки и модели.
  Однако `.gitignore` не отменяет отслеживание файлов, уже добавленных в Git.
  Проверять каждый файл перед добавлением; не коммитить секреты или данные.
- Перед передачей изменений сначала добавить и проверить только файлы,
  предназначенные для публикации, затем коммитить и отправлять их в
  согласованный удалённый репозиторий. На Lenovo получать изменения через
  `git pull`.
- `.env.example` предназначен только для безопасных примеров параметров.
  Настоящие секреты и конфигурацию машины не передавать.

## Проверки готовности целевой машины

После реализации архитектуры проверять на Lenovo, а не только на ASUS:

1. Установка проекта с чистого клона по закреплённым версиям Python и
   зависимостей, без IDE.
2. Запуск всех тестов и основной команды приложения.
3. Локальный запуск выбранной AI-модели без CUDA и NVIDIA.
4. Время запуска и обработки, пиковое потребление RAM и стабильность на
   реальных целевых сценариях.
5. Удаление тестовой установки и повторение процедуры с нуля для проверки
   воспроизводимости.

Конкретные допустимые пороги производительности следует согласовать вместе
с архитектурой и сценариями использования.
