# ADR-0001: Модульный монолит и направление зависимостей

- **Статус:** принято. Это фиксирует архитектуру и границы MVP; параметры
  реализации ниже остаются предметом выбора и проверки.
- **Дата:** 2026-11-20
- **Область:** архитектура приложения и границы модулей

## Контекст

Нужно постепенно развивать локальное приложение для проверки закупочных
позиций на Windows-компьютере с 16 ГБ RAM. Price Checker MVP должен принимать
несколько позиций вручную или из Excel и обрабатывать 100+ позиций с
независимыми статусами и сохраняемыми результатами. В перспективе запланированы
разбор договоров, профили, правовые материалы, консультации и отчёты.
Облачные AI API, CUDA и платная инфраструктура не являются предпосылками.

## Решение

Принят модульный монолит с Clean Architecture-подобными слоями:
Domain, Application, Infrastructure и Presentation. Price Checker —
единственный бизнес-модуль MVP. Будущие модули документированы, но не создаются
в виде пустых пакетов. Domain остаётся независимым от библиотек и провайдеров;
Application владеет портами сценариев, Infrastructure реализует порты,
Presentation вызывает Application. Composition root связывает реализации.

Локальная SQLite и внутренняя очередь фоновых заданий предпочтительны для
первого релиза. Redis, брокер сообщений и микросервисы не вводятся без
измеренного требования.

Price Checker MVP включает обязательный автоматический поиск товаров через
бесплатный источник, а также ручной ввод и импорт `.xlsx`: выбор листа и строки
заголовков, сопоставление колонок, построчный предпросмотр, валидацию и
исправление/исключение строк, редактирование позиций до старта. Если
автоматический поиск недоступен, специалист использует резервную ручную
вставку URL. Конкретный бесплатный поисковый провайдер пока не выбран. Парсинг
произвольных договоров и OCR принадлежат будущему Document Intelligence и не
входят в MVP.

## Порты и контракты

Порты принадлежат Application того модуля, которому они нужны. Это контракты
архитектуры; до реализации не требуется создавать пустые файлы или общую
иерархию адаптеров.

| Порт | Владелец и назначение | MVP |
|---|---|---|
| `SearchProvider` | Price Checker: обязательный автоматический запрос поиска через бесплатный источник → кандидаты URL и метаданные/ошибки провайдера | Да; конкретный провайдер пока не выбран |
| `ProductPageExtractor` | Price Checker: допустимая страница → наблюдения товарных полей с provenance | Да для утверждённых источников |
| `StorageRepository` | Роль хранилища Price Checker. Реализуется узкими портами, например `ReviewRunRepository`, `OfferObservationRepository`; не единый универсальный CRUD | Да |
| `ReportExporter` | Price Checker: DTO отчёта → экспортированный артефакт | Да, для одного утверждённого формата |
| `DocumentParser` | Будущий Document Intelligence: документ → текст/кандидаты позиций/неопределённость и ссылки на фрагменты | Нет; MVP принимает введённые или импортированные позиции |
| `OCRProvider` | Будущий Document Intelligence: страницы изображения/PDF → текст, геометрия и уверенность распознавания | Нет; нужен при принятии поддержки сканов |
| `AIProvider` | Не общий произвольный completion API. Будущий специализированный порт допустим лишь для конкретной задачи, например предложения атрибутов товара; ответ — непроверенная подсказка, не решение | Нет; без AI для MVP |

`DocumentParser`, `OCRProvider` и `AIProvider` — зарезервированные роли для
реальных будущих сценариев, а не требование немедленно создать пустые
абстракции. Перед их введением контракт определяется по первому реальному
адаптеру и тестируемому сценарию.

## Импорт, наблюдения и версии политик

Предпросмотр Excel не создаёт постоянные позиции; подтверждённые строки
добавляются в черновик запуска. Невалидные строки исправляются или явно
исключаются. Точные дубликаты в предпросмотре помечаются, но автоматически
не сливаются: это могут быть самостоятельные строки закупки. Повтор команды
подтверждения с тем же idempotency key не создаёт новые позиции.

Каждое получение предложения создаёт неизменяемую `OfferObservation` с
URL, временем получения и доступными фактами о продавце, товаре, цене,
валюте, НДС и доставке. Новая цена не обновляет предыдущую запись.
Сопоставление объявлений с тем же листингом возможно только при стабильном
ID источника или подтверждении; идентичность товара не выводится только из
названия или URL. В MVP нет каталога товаров и отдельной аналитики.

Будущий модуль профилей владеет данными профиля и декларативными правилами,
включая категорийные обязательные характеристики. Для запуска он передаёт
Price Checker версионированный `ReviewPolicySnapshot`. Price Checker хранит
собственную неизменяемую копию/хеш snapshot в запуске и не читает таблицы
профилей. Изменение профиля не меняет исторические результаты; до появления
модуля профилей применяется базовая политика Price Checker.

## Очередь и транзакции

Несколько запусков обрабатываются независимо одним экземпляром приложения.
Task имеет уникальность по `(run_id, item_id, operation, generation)`;
повторная отправка одного request защищена idempotency key. Одинаковые
описания в разных строках сохраняются как разные позиции с отдельными
результатами. Повтор поиска — явное новое поколение задачи, а не случайная
повторная постановка. После старта версия входной позиции зафиксирована;
изменение требований не переписывает данные выполняемого запуска.

Начальная настройка для измерений на Lenovo — два worker, локальный предел
четыре и более низкие лимиты по правилам конкретного провайдера/домена.
Изменение статуса и claim выполняются короткой транзакцией. Сетевой запрос,
ожидание retry и извлечение данных происходят вне транзакции; результат
сохраняется отдельной короткой транзакцией. SQLite leases позволяют после
перезапуска выявить незавершённые задания и восстановить их без потери
записанных наблюдений. Отмена прекращает новые запросы и оставляет уже
сохранённые результаты.

## Рассмотренные варианты

### Микросервисы

Отклонены для текущего масштаба: локальная однопользовательская установка,
отсутствие независимого масштабирования и дополнительная стоимость настройки
и сопровождения не оправдывают разнесение по процессам.

### Монолит без модульных границ

Отклонён: интеграции поиска, документы, сравнение и будущая правовая логика
могли бы напрямую зависеть друг от друга и усложнить замену провайдеров.

### Облачные API и AI

Отклонены как обязательные зависимости: конфиденциальные документы не должны
передаваться внешнему AI-сервису; платные API не входят в ограничения.
Публичный веб-поиск, если подключается, получает только минимизированный
запрос и требует отдельной проверки правил провайдера.

### Тяжёлая очередь заданий

Redis и отдельный брокер не вводятся, пока локальная очередь SQLite и
ограниченные workers проходят целевые испытания на Lenovo.

## Последствия

Положительные:

- бизнес-правила и тесты не зависят от сетевых и DB-библиотек;
- провайдеры и форматы отчётов можно заменять через локальные порты;
- текущая поставка остаётся локальной и пригодной для целевого компьютера;
- ошибки и ручные решения сохраняются отдельно от извлечённых фактов;
- Excel и ручной ввод покрывают позиции без преждевременного включения
  парсинга договоров;
- append-only наблюдения позволяют построить будущую историю цен без
  перезаписи исходных данных;
- неизменяемые снимки политики изолируют прошлые проверки от обновлений
  профилей.

Ограничения и стоимость:

- конкретный бесплатный поисковый провайдер ещё не выбран; ручная вставка URL
  допускается только как резервный сценарий недоступности автоматического поиска;
- SQLite требует коротких транзакций и проверки восстановления очереди;
- работа предполагает один процесс приложения; конкурентные запуски внутри
  него должны быть испытаны на 100+ позициях;
- профили, отдельный Report Generator и другие модули потребуют последующих
  решений и миграций.

## Проверки перед утверждением

- Нет импортов из Domain в Infrastructure/Presentation.
- Модули не импортируют внутренние модели друг друга.
- Нет интерфейсов, не привязанных к сценарию или реальной замене.
- Нет единого «god service» для поиска, сравнения, хранения и отчётов.
- В MVP нет обязательных облачных сервисов, платных API или CUDA.
- В MVP обязателен автоматический поиск через бесплатный источник; ручная
  вставка URL — резервный сценарий; договорный парсинг/OCR
  отложены в Document Intelligence.
- Импорт исправляет/отклоняет ошибки построчно, а подтверждение идемпотентно.
- Исторические offer observations append-only и не сливаются по одному названию.
- Каждый запуск хранит snapshot политики без доступа Price Checker к таблицам
  будущего модуля профилей.
- Многозапусковая нагрузка 100+ позиций проходит тесты без сетевых операций
  внутри DB-транзакций.
- Выбраны и проверены поисковый провайдер, правила сопоставления, формат отчёта
  и измеримые пределы производительности.
